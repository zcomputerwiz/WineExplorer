This is a static inventory of the requested snapshot and lab workflows, not every repository tool. Entries below
were checked against the named files; they describe commands for later use, not
commands executed during this inventory. Hundreds of additional files exist under

## Recipes

These are source-derived commands for a later coordinated run, not tested by this documentation pass. In Debian WSL set `LAB=/mnt/d/DeepThought/ChromiumLab`. VM B uses SSH 2236; the fixed MSI tracing/deployment wrappers below use VM A on 2235. Coordinate disk and guest ownership first.

For the historical combase experiment on **A**, place both builds under `msi-fixval-20261105/dlls/{x86_64-windows,i386-windows}/combase.dll`, then `bash "$LAB/msi-fixval-20261105/deploy.sh"`. It replaces the shared runtime and retains one dated backup per architecture; verify hashes and restore deliberately. The services variant is `bash "$LAB/msi-svc-r4-20261105/deploy-svc.sh"` on A.
3. **Browser fixture and result.** On B, with the fixture, helper scripts, installer and runtime already in their hardcoded guest locations, `bash "$LAB/chromium-installer-20261105/run-validate5.sh"`; it deletes guest `chromium-5` and launches asynchronously. Poll `bash "$LAB/g-b.sh" 'cat /home/debian/development-validation-20261101/chromium-5/result.json'` until `finished` appears; inspect `error`, `install_exit`, `fixture` and `chromium_functional`, not merely launcher success. The private-loopback fixture installs from the local mini installer and uses a local HTTP fixture.
4. **Fresh installer with internet.** On B, with the named Edge MSI and runtime already present, `bash "$LAB/chromium-installer-20261105/run-edge-net.sh"`; poll `bash "$LAB/g-b.sh" 'tail -30 /home/debian/edge-net.log'` for `DONE` and `MSI_EXIT`, then inspect `/home/debian/edge-net-20261105/msi.log`. This deletes that fixed output/prefix, uses the guest network, and has 120-second wineboot and 600-second MSI timeouts; do not wrap it in `--private-loopback`.
5. **Pull results.** After completion, `bash "$LAB/chromium-installer-20261105/pull5.sh"` copies four named B artifacts into existing `run5/`, overwriting names. Those overwrite their dated local result names and tolerate some missing files; check completeness.

## Pitfalls and standing rules

* Git Bash: set `MSYS_NO_PATHCONV=1` when passing Linux paths through `wsl`; Git Bash `/tmp` and WSL `/tmp` are different locations.
* Never pass C escapes or backslashes through heredocs, `sed`, or `python -c`; inspect edited lines. Windows Python text mode can rewrite LF to CRLF: use `newline=''` when editing Wine text and inspect `git diff --stat` and the actual diff.
* Several legacy harnesses kill wineserver, services.exe or Xvfb globally, delete fixed prefixes, and overwrite logs. Only one agent may use such a distro at a time. An owned prefix alone does not protect other processes from `pkill`.
* Guest disks fill: remove only confirmed superseded, owned prefixes after coordinating with their owner. VM B can auto-stop (`WEX_VMB_SECONDS`); check its configured lifetime against the test.
* On the Windows host, execute only our own test executables. A compile, window-DC sample or screenshot alone does not establish presented-pixel correctness; validate visible screen pixels and fresh-prefix guest behavior when required.
