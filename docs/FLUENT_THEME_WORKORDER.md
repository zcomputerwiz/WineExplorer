# Work order (Gemini): the Fluent (Windows 11 style) theme, complete and installable

Status: ready, 2026-10-16. Assignee: Gemini.

## Goal

"Fluent (Windows 11 style)" becomes a complete theme a user picks in Display Properties on an installed system.

- Its icons cover everything the shell shows.
- It comes with a cursor set.
- It is packaged into the ISO.
- Optionally, Linux programs get a matching GTK theme.

Built-in Luna, Royale and Classic are unchanged.

Start from:
- `docs/THEMES.md`, "Open icon packs";
- `assets/iconpacks/fluent.json` and `scripts/build_iconpack.py`;
- `docs/iconpacks/fluent.md` (provenance);
- `docs/ASSETS.md` (what art may be used);
- `LICENSE.md` (licence table).

## Rules for art (read `docs/ASSETS.md` first)

- **Sources.** Only art under the licences listed there. Proprietary Microsoft art never enters the repository.
- **Rip check, for every new third-party source, before using it.** Record the result in `docs/ASSETS.md`.
  1. Scan its files for embedded raster images (`data:image` inside SVGs).
  2. Compare its renders against the genuine Windows icons and cursors, kept locally in
     `../WineExplorer-local/ms-assets/win11/` (shell icons) and `C:\Windows\Cursors` (cursors). Any near-pixel match
     (RMSE close to 0) means the source is excluded.
  3. Exclude any author already found ripping. yeyushengfan258 is excluded, cursors included.
- **Local comparisons only.** Side-by-side comparisons with Windows 11 are made with
  `../WineExplorer-local/tools/compare_icons.sh`, and the sheets stay in `../WineExplorer-local/notes/`. Never commit
  them, and never name Windows' own files in the repository.
- **Our own work.** Shapes come from allowed sources. Colours are matched by eye. Nothing is traced from Windows art.
- **Provenance.** Every icon's provenance is generated by `build_iconpack.py --provenance` and committed.
- **Licences.** Every new source is pinned to a commit in the mapping and gets a row in `LICENSE.md`.

## Phases (one review at the end; commit and push your branch after each phase)

**T1. Applying a pack works.**
- Bug: `explorer /theme:<name>` stores only the theme's short name in
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\CurrentTheme`. But `src/dlls/wexres/shellres.c`
  (`theme_pack_dir`) reads `IconPack=` from that value as a `.theme` path, so the pack is never found.
- Fix it where the value is written (`src/dlls/themeui/theme_engine.c` and the `/theme:` handling): resolve a name to
  `%WinDir%\Resources\Themes\<Name>\<Name>.theme` and store the full path.
- Check that Display Properties (`src/dlls/desk.cpl/theme_page.c`) lists themes installed in their own folder, such
  as `Resources\Themes\Fluent\Fluent.theme`, and applies them live: icons reload through `WM_THEMECHANGED` without
  logging off.
- Test: apply Fluent, then Luna, then Fluent again from Display Properties in the real shell, with screenshots.

**T2. Package it.**
- Build the Fluent pack as part of `installer/package-wine.sh`. Fetch the pinned sources in the build environment,
  as sparse checkouts at the commits in the mapping. Do not vendor the sources into the repository.
- Install the result under `Resources\Themes\Fluent` in the shared machine root, beside Luna and Royale (see
  `scripts/setup-machine-root.sh`), with its `LICENSE*` files.
- A failed pack build must not break the ISO build: skip the pack with a clear message.

**T3. Complete the icons.**
- Find every icon the shell shows that the pack does not yet cover, and add it to `fluent.json`:
  - special folders: My Documents, My Pictures, My Music, My Videos, Desktop, Downloads, Shared Documents (see the
    `DefaultIcon` sections of `src/resources/themes/*.theme`, and shell32 235 and friends);
  - Control Panel applets (their own `xpres_<module>.dll`, through `shellres.c`);
  - program icons the Start menu and desktop show (`shellres_app_icon`: Internet Explorer, Notepad, Calculator,
    Paint, Command Prompt, Windows Media Player);
  - the taskbar and tray icons that come from the pack.
- Extend `build_iconpack.py` to build several `xpres_<module>.dll` from one mapping if needed.
- Compare each slot with Windows 11 locally. Commit the regenerated `docs/iconpacks/fluent.md` and
  `fluent-preview.png`.

**T4. Cursors.**
- Find a Windows 11-like cursor set under an allowed licence and run the rip check against the host's cursors.
- If none passes, draw the main ones yourself from open shapes: arrow, busy, working in background, text, hand,
  move, the four resize cursors, unavailable, help and precision select. Document the shapes and colours.
- Build `.cur` and `.ani` files at the standard sizes, ship them as separate files of the theme (never compiled
  into our program binaries), and name them in the `.theme` (`[Control Panel\Cursors]`).

**T5 (optional). Linux programs.** If time allows:
- generate a matching GTK 3/4 theme with the Azurra framework (B00merang-Project, GPL-2.0);
- apply it in the session only while Fluent is the current theme, through a hook in
  `scripts/wine-explorer-session-common.sh`, the shared file of both sessions (see Boundaries);
- leave GTK alone for other themes.
