## Findings

### F1 [P2] Validate review operation IDs and reject zero-total progress

File: [`src/dlls/wexhost/unixlib.c`](https://github.com/zcomputerwiz/WineExplorer/blob/2bc4555bcf40ba37862c87b511c563ceb2c7e27d/src/dlls/wexhost/unixlib.c)

The START_REVIEW acknowledgement parser accepts any non-whitespace token as
`op_id` (`sscanf("OK %95s STARTED%n", ...)`) and returns success without
checking the coordinator's ID grammar. The coordinator generates IDs in the
form `review_<verb>_<32 lowercase hex digits>`. The resulting value is later
sent back in QUERY_REVIEW/CANCEL_REVIEW requests. Single-line framing and a
length limit do not prove that the field is a valid operation ID. This leaves
the explicit Round 1 requirement to validate operation IDs incomplete.

The RUNNING progress parser also accepts `STATUS RUNNING 0 0\n`: it checks
only `done <= total`. A real review download has a positive catalog byte total.
Zero *done* is valid at the start, but zero *total* is not. The existing tests
cover boundary and malformed decimal cases but not this zero-total frame.

Required repair/proof:

- Require the STARTED ID to match the exact protocol grammar and the component
  verb requested (for example, `review_corefonts_<32 lowercase hex>`); reject
  malformed, wrong-verb, uppercase, short/long, and extra-token acknowledgements.
- Reject RUNNING progress with total zero while retaining `done == 0` when
  total is positive.
- Add negative and positive controls to `scripts/test_oobe_bridge.py`, exercising
  the compiled production C seam. Verify malformed acknowledgements never
  return success or populate an accepted ID.

### F2 [P2] Escaped lone surrogate still lets damaged terms suppress catalog

File: [`scripts/wex-components.py`](https://github.com/zcomputerwiz/WineExplorer/blob/2bc4555bcf40ba37862c87b511c563ceb2c7e27d/scripts/wex-components.py)

The JSON-read exception handling correctly maps malformed JSON and invalid UTF-8
to `StaleTermsError`. However, valid JSON can contain an escaped lone surrogate
(e.g. `{"text":"\\ud800", ...}`), which Python decodes into a string containing
that surrogate. At the later `text.encode('utf-8')` used for rendered-text
fingerprint validation (around line 1107), `UnicodeEncodeError` escapes.
`review_state()` catches `StaleTermsError`, not this encoding failure; therefore
a damaged cached document can still abort GET_COMPONENTS and hide sibling rows,
the failure mode F2 was intended to eliminate.

Required repair/proof:

- Treat non-UTF-8-encodable cached text as damaged/stale review data, without
  weakening path, owner, mode, size, or strict package-cache checks.
- Add a regression fixture with an escaped lone surrogate. Assert catalog
  enumeration remains nonempty, the affected row is not advertised as cached,
  strict GET_TERMS fails closed, siblings remain available, and no implicit
  download/install or acceptance occurs.
