# Luna and merged-master review, 2026-10-17

Reviewed `db706602` (Open Luna round 2) and `b63bac04` against their parents.
The repository's default branch is `master`, not `main`. `b63bac04` was already
the local and remote master tip: it changes only two reports and a raw build
log. Its log ends with `Wine build complete.` and a successful compositor
`ninja` run. It does not claim that the later resource changes were tested in
the earlier ISO. The documented restored-window scaling problem remains open.

The initial Luna review was too shallow: well-formed XML and Gemini's Wine
screenshots did not establish native XP parity. This review also inspected
the running XP VM's own Luna desktop, Start menu, captions, task panes,
unlocked toolbar handles and notification toggle. Reference screenshots were
kept outside this repository. No reference pixels, sampled colors, extracted
art or Windows logo were put into the theme. Adjustments use the existing
open SVG geometry or independently drawn paths, circles, rectangles and
gradients, with color adjustments made by eye.

## Corrections included with the merge

- Correct the horizontal toolbar background's nine-slice margins in all three
  font schemes. The replacement `TaskBandButtonNoEdge` has six 24-pixel states;
  the old 18+8 and 21+5 vertical margins exceeded each state. The corrected
  margins are `8, 3, 3, 3` for toolbar buttons, dropdowns and overflow buttons.
- Preserve alpha in the rounded scrollbar arrows/thumbs, task-pane heads and
  chevrons, and Start-menu top corners. Remove explicit magenta backdrops from
  the pane heads and chevrons, rather than antialiasing against magenta.
- Draw double task-pane chevrons, a larger green All Programs arrow, a pale
  account-picture well, and a less semicircular Start-button end cap.
- Match the lighter Start-menu header/footer and cyan tray by eye. Remove the
  orange stripe from ordinary checked task buttons; native XP does not use
  that stripe to indicate every active window.
- Match the inactive caption, window border and caption-button palette to
  XP's lavender blue and muted pink, including the small-button sources.
- Use pale blue normal task-pane bodies and a lighter special-group body.
- Add editable horizontal scrollbar thumb, track and grip sources to match
  the vertical controls; the inherited horizontal artwork was still gray.
- Add independently drawn blue notification toggles for collapsed/expanded
  states, blue toolbar grips in both orientations, and forward double
  toolbar-overflow chevrons. The inherited tray toggle was gray, with the
  toolbar grips and overflow glyphs also visibly unlike the native reference.

## Verification

The corrected style builds with the production `build_msstyles.py`, librsvg,
ImageMagick, Pillow and MinGW on local Debian and on the existing build VM.
All 58 SVGs render through the actual production conversion function. The
review checks 16 alpha-backed assets for transparent corners and visible
magenta contamination, and 168 SVG-backed nine-slice definitions across the
three font schemes. The intentional one-pixel frame-side strip is excluded
from the ordinary source-margin check. All checks pass.

Live checks used the existing pinned combined i386/x86_64 WineExplorer build,
an isolated prefix, and a dedicated 1024x768 Xvfb display. Both distinct review
executables were compiled and run; these are not Gemini's duplicate control
screenshots. Their ordinary controls and both scrollbar directions remain
usable through Classic/Luna switches. This is not a new comctl32-v6 acceptance
suite or a fresh ISO-install test.

## Findings retained for later review

1. **P2, existing tray interaction:** expanding on mouse-down can move an icon
   under the pointer before mouse-up. One real-pointer check opened Volume
   after expansion. `systray.c` changes `tray_expanded` and rearranges icons in
   `WM_LBUTTONDOWN` without capturing the matching release. Investigate
   releasing on the original target or committing the toggle on mouse-up.
   The issue is outside the resource-only changes and should be reproduced
   in an installed session before a runtime fix.
2. **P2, existing Classic Explorer fallback:** some task-pane headers have
   blue text on a blue fallback fill, with poor contrast. The Classic
   [toolbar screenshot](screenshots/review-classic-toolbar.png) also records
   this. The taskbar, toolbar fallback, window controls and scrollbars still
   switch correctly. No theme-engine or Explorer runtime code was changed.
3. **Evidence limitation:** Gemini's `r2-05-control32.png` and
   `r2-05-control64.png` are byte-identical (SHA256
   `a51eb02dfdfe61f55d316b45178f2423a34553ed094c8635292cbe412c920f23`).
   They cannot independently establish separate architecture coverage.
4. **Existing Wayland follow-up:** restored-window live scaling remains
   unresolved, as explicitly documented in `b63bac04`'s reports.

These observations do not identify a runtime regression introduced by the
two reviewed commits. The resource corrections can be integrated while
retaining the existing runtime and acceptance follow-ups.

## Review environment notes

Initial sandboxed Git status failed when inspecting `wexcomp`; use
`--ignore-submodules` for this resource review. An attempted write-tree check
also hit the read-only Git metadata boundary; the actual merge was prepared
through the approved Git command. The first VM archive transfer was blocked
by automatic approval review, then explicitly approved by the user. Debian
needed `librsvg2-bin` and `python3-pil` for local compilation.

VM extraction initially warned about future archive timestamps; subsequent
extraction used `tar -xm -f`. Initial fixture startup exited unsuccessfully
around prefix initialization/server shutdown; the initialized prefix was
usable and the script was corrected to tolerate an already-stopped server.
An unquoted Windows path arrived as `C:windowsResourcesThemesClassic.theme`;
constructing the path inside the fixture fixed `apply ...=0`. Early property
sheet attempts logged `FAIL no taskbar property sheet` because of menu focus
and asynchronous setup; later successful applies and registry/setting-change
checks are retained in the same raw log. Named/host desktop routing and
missing host decorations initially confused the fixture; a virtual Default
desktop aligned the visible shell, notification recipient and test windows.
Captures were repeated after startup and theme redraws settled.

The unrelated host `.gitignore` edit is excluded. The XP reference VM remains
running, with its taskbar restored to locked. The disposable review prefix
and generated build files are retained on the build VM for reproduction;
its Wine server and dedicated Xvfb display are stopped after review.
