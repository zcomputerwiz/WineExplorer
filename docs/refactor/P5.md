# P5 extension-point assessment

Assessment complete against retained Wine d0a0af0681. No additional DLL is
introduced: the remaining candidates do not have an existing extension path
that substitutes for the modified behavior. They remain indexed X changes.
This optional source review ran while P4's full build was in progress; P4's
runtime/install acceptance is still required.

| Candidate | Existing support and evidence | Decision |
|---|---|---|
| Send To | shlview_cmenu.c constructs the submenu at 570 and uses private selection/menu state and command offsets. Item context-menu initialization still has the TODO to enumerate shellex at 1731. shlexec.c's ContextMenuHandlers support invokes a default verb; it does not populate this shell-view menu. | Keep X. Registering a handler alone would not replace the submenu; adding menu enumeration is another Wine feature/hook. |
| New submenu | The implementation exposes IShellExtInit/IContextMenu3/IObjectWithSite, but shlview_cmenu.c:1849 calls new_menu_create directly. It also depends on private PIDL classification and shell32 resources. | Keep X. Changing creation into registry activation would add a hook; COM-shaped implementation alone is not existing registered dispatch. |
| Open With | openwith.c implements SHOpenWithDialog and helper operations consumed directly by the item menu and file Properties Change button. A registered handler does not replace these direct calls. | Keep X. Moving just a context submenu would leave the dialog/helper implementation duplicated or require new entry-point dispatch. |
| File Properties | SHCreatePropSheetExtArrayEx enumerates shellex/PropertySheetHandlers; DoOpenProperties adds extension pages after the built-in pages. Current changes alter the built-in General page, its private file_properties_info and its apply/rename logic. | Keep X. An added extension page would duplicate rather than replace the modified page. |
| Namespace labels/known-folder behavior | Wine supports registered namespace classes and registry display names. Current retained changes affect built-in folder implementations and their PIDL/name behavior. Project namespace lookup/alias helpers already live in wexres after P3b. | Keep remaining X. Replacing the built-in objects would copy their wider IShellFolder behavior; small label resources alone do not remove those implementation changes. |
| Filmstrip/thumbnail/group view behavior | The retained changes are in shlview.c's internal layout, selection, image/preview and refresh paths, rather than an extension-owned view selected through a current registration point. | Keep X. A replacement view is a broader subsystem and would duplicate tested file-view behavior. |

The supported property-page and default-verb paths remain available for
future additive features. Generic context-menu enumeration should be an
independent upstream feature before moving Send To or New through it.
No extra test run is claimed for this source-only assessment; P2/P3/P3b
acceptance continues to cover the retained implementation.
